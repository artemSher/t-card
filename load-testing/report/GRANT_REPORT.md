# Отчёт о нагрузочном тестировании платформы T-Card

**Дата проведения тестирования:** 15 августа 2026 г.  
**Версия приложения:** 1.0.0  
**URL тестируемого приложения:** https://t-card.vercel.app  
**Инструменты тестирования:** k6 v2.2.0, Lighthouse CI  

---

## 1. Цели и задачи тестирования

### 1.1 Цели
- Оценка производительности платформы T-Card при различных уровнях нагрузки
- Определение предельной пропускной способности системы
- Проверка стабильности работы при длительной нагрузке
- Выявление узких мест и рекомендации по оптимизации

### 1.2 Задачи
1. Провести нагрузочное тестирование с профилями: 50, 100 и 500 одновременных пользователей
2. Выполнить soak-тест (тест стабильности) длительностью 10 минут
3. Провести фронтенд-аудит производительности
4. Сформировать рекомендации по оптимизации

---

## 2. Методология тестирования

### 2.1 Инфраструктура
- **Хостинг:** Vercel CDN (глобальная сеть доставки контента)
- **Архитектура:** Single Page Application (SPA) на React 19 + Vite 8
- **Тип приложения:** Статический сайт с клиентским роутингом

### 2.2 Сценарии тестирования

#### Нагрузочный тест (Load Test)
- **Профиль 1 (Light Load):** 50 виртуальных пользователей
  - Плавный рост: 0 → 50 VUs за 30 секунд
  - Удержание: 50 VUs в течение 1 минуты
  - Плавный спад: 50 → 0 VUs за 15 секунд
  
- **Профиль 2 (Medium Load):** 100 виртуальных пользователей
  - Плавный рост: 0 → 100 VUs за 30 секунд
  - Удержание: 100 VUs в течение 2 минут
  - Плавный спад: 100 → 0 VUs за 15 секунд
  
- **Профиль 3 (Stress Load):** 500 виртуальных пользователей
  - Резкий рост: 0 → 500 VUs за 30 секунд
  - Удержание: 500 VUs в течение 1 минуты
  - Плавный спад: 500 → 0 VUs за 15 секунд

#### Soak-тест (Stability Test)
- **Профиль:** 100 виртуальных пользователей
- **Длительность:** 10 минут непрерывной нагрузки
- **Цель:** Выявление утечек памяти и деградации производительности

### 2.3 Тестируемые страницы
1. Главная страница (выбор роли)
2. Страница входа соискателя
3. Страница входа работодателя
4. Статические ресурсы (CSS bundle)

## 8. Рекомендации по оптимизации

### 8.1 Краткосрочные (1-2 недели)

1. **Code Splitting**
   - Разделить JS-бандл на чанки по маршрутам
   - Ожидаемый эффект: ↓ 30% initial load time
   
2. **Preload критических ресурсов**
   ```html
   <link rel="preload" href="/fonts/inter.woff2" as="font" crossorigin>
   <link rel="preload" href="/assets/logo.svg" as="image">
   ```
   - Ожидаемый эффект: ↓ 15% FCP

3. **Настройка кэширования**
   - Vercel headers для статики: `Cache-Control: public, max-age=31536000, immutable`
   - Ожидаемый эффект: ↓ 50% повторных запросов

### 8.2 Среднесрочные (1-2 месяца)

4. **Lazy Loading компонентов**
   ```javascript
   const Assessments = lazy(() => import('./pages/employee/Assessments'));
   const Analytics = lazy(() => import('./pages/employer/Analytics'));
   ```
   - Ожидаемый эффект: ↓ 40% bundle size

5. **Оптимизация изображений**
   - Использовать WebP/AVIF вместо PNG
   - Ожидаемый эффект: ↓ 60% размер изображений

6. **Service Worker для offline-режима**
   - Кэширование критических ресурсов
   - Ожидаемый эффект: мгновенная загрузка при повторных визитах

### 8.3 Долгосрочные (3-6 месяцев)

7. **Server-Side Rendering (SSR)**
   - Переход на Next.js для улучшения SEO и FCP
   - Ожидаемый эффект: ↓ 50% FCP, улучшение SEO

8. **CDN для API**
   - При появлении бэкенда использовать edge-функции Vercel
   - Ожидаемый эффект: ↓ 30% API latency

## 10. Приложения

### 10.1 Команды для воспроизведения тестов

```bash
# Установка k6
brew install k6

# Нагрузочный тест (50/100/500 VUs, ~7 минут)

# Soak-тест (100 VUs, 10 минут)

  --quiet --chrome-flags="--headless"

# Генерация отчёта
```
